# Тестирование веб-приложения Codebattle

[![Autotests Status](https://github.com/Skifca/qa-engineer-java-from-scratch-project-85/workflows/hexlet-check/badge.svg)](https://github.com/Skifca/qa-engineer-java-from-scratch-project-85/actions)

## Описание проекта
Проект посвящен проведению полного цикла ручного тестирования игровой веб-платформы Codebattle, предназначенной для соревновательного программирования между разработчиками в режиме реального времени. 

В ходе работы выполнены анализ и формализация требований (функциональных, нефункциональных и неявных), спроектирована тестовая документация (покрытие игровых сессий, онлайн-синхронизации кода, чата, игры с ботом, песочницы и мобильной адаптивности), проведено функциональное тестирование с фиксацией результатов и привязкой выявленных дефектов к репозиторию проекта.

---

## Структура репозитория
Все конфигурационные YAML-файлы проекта расположены в директории `code/` для автоматической проверки:

* **`code/requirements.yml`** — формализованный перечень функциональных, нефункциональных и неявных (implicit) требований к веб-платформе.
* **`code/test-cases.yml`** — тестовые сценарии, покрывающие ключевой функционал: создание комнат, дуэли в реальном времени, игру с ботом, работу чата, проверку песочницы (sandbox), мобильную верстку и краевые случаи.
* **`code/testing-report.yml`** — отчет о результатах выполнения тест-кейсов со статусами `pass` и `fail`.
* **`code/issues.yml`** — перечень ссылок на зарегистрированные задачи (Issues) с багами на GitHub.
* **`code/reopened_issues.yml`** — перечень ссылок на повторно открытые задачи после проведения ретеста.

---

## Выполненные задачи и результаты
1. **Анализ требований:** Выделены ключевые пользовательские сценарии (создание комнат с выбором языка программирования, дуэли в реальном времени, игра с ботом, отслеживание результатов в лидерборде, приватные игры по ссылке).
2. **Тест-дизайн:** Создана полнофункциональная тестовая модель, включающая проверки изоляции кода (Sandbox), безопасность от редактирования кода соперника, неявные сценарии (дисконнект, перезагрузка страницы) и адаптивность под мобильные экраны.
3. **Выполнение тестов и локализация дефектов:** Выявлены дефекты в валидации кириллических символов при регистрации, сбои при обработке внезапного разрыва соединения и некорректное отображение статуса онлайн у гостей.
4. **Управление дефектами:** Все найденные дефекты и повторно открытые задачи зафиксированы и систематизированы в файлах `issues.yml` и `reopened_issues.yml`.
